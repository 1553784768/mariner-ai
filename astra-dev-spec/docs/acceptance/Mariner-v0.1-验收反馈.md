## 4. 对你提出的 5 项改进的评估

| 需求 | 判断 | 风险与处理 |
|---|---|---|
| 日报等内容汇总成知识库，可手动编辑 | 合理，而且是对话功能的基础 | 编辑只影响问答，不影响计算（按你的选择）。订单和影响单的条目由系统生成，设为只读，否则会出现「知识库里写的数字」和「引擎算出的数字」互相矛盾 |
| 采纳时选择具体哪几条建议 | 必要。现在的「采纳」记录不到采纳了哪一条，审计意义很弱 | 建议列表可能在下次重算后变化：已选中的建议文本只要有一条不在新列表里，处理状态就重置为待处理 |
| 「需补充」弹出输入框 | 必要。后端已支持 `note` 字段，只是前端没有接上 | 输入框获得焦点时必须屏蔽全局快捷键，与 P1 一起修 |
| 首页 AI 工作台：对话 + 多模态导入订单 | 合理，但与原有的「订单数据不发给模型」约束冲突 | 按你的选择：导入文件时每次弹窗确认后才发送给模型；对话默认不使用订单数据，开启开关后才使用（这是我的设定，见下方）。模型生成的订单行必须先经过与 CSV 相同的校验，再由人工确认导入 |
| 中英文切换（界面和生成内容都双语） | 可做，工作量最大的一项 | 引擎建议是中文模板，我设计成「把中文结果解析回模板再渲染英文」，不改引擎；分诊和抽取改为同时输出中英文，模型调用的输出变长 |

**以下 2 项是我替你定的，不同意可以在规格中直接改：**

1. 工作台对话中「使用订单数据」开关默认关闭。打开后，对话会把检索到的订单和影响单内容发给模型，并在界面上提示这一点。
2. 知识库检索使用 SQLite 自带的 FTS5 trigram 分词，不引入向量库，也不调用嵌入接口。中文查询少于 3 个字时改用 LIKE 匹配。
